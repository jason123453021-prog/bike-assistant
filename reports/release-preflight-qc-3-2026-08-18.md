## 二、核心資料與背景生命週期稽核

核心資料鏈由騎乘生命週期守門統一限制：只有有效騎乘狀態才能累計距離、活動／移動／暫停時間、海拔、功率與卡路里。GPS 點位品質、海拔濾波與持久化批次處理的回歸均通過，因此弱訊號、漂移點、短暫中斷及背景返回時不應將單一壞點放大為距離或爬升暴衝。[4]

背景任務仍以本機狀態與軌跡批次保存為主。停止騎乘會標記背景狀態為非騎乘並停止定位更新；回到前景只恢復仍為有效騎乘的資料。補給待確認狀態、雙通道智慧補給與每小時碳水上限均維持既有資料鏈，不會因本輪清理而改寫。[4] [1]

## 四、權限、離線與介面邊界

若精確定位、背景定位或通知權限未授予，開始騎乘前的準備流程會提供中文說明並阻止不完整啟動，避免白屏或未記錄卻誤以為開始騎乘。背景追蹤無法啟動時，App 會清楚說明僅能在前景持續記錄的限制。[5]

本機騎乘統計、軌跡批次、補給倒數、設定、騎乘活動、分享文案與通知狀態皆可在沒有網路時使用。即時地址搜尋、公開路線規劃與新地圖瓦片本質上需要外部資料來源；本輪已確保這些按需功能失敗時改由同頁說明安全退化，而不清除正在進行的本機騎乘或跳出請求失敗警告。[6]

安全區、對比與防誤觸採既有回歸守護；所有面向使用者的 Pressable 已排除空白 `onPress`。Android PiP、系統級懸浮窗、`SYSTEM_ALERT_WINDOW`、C++ 原生模組及 NitroModules 均不在正式程式或發布設定中。[5] [8]

## 五、發布配置與套件健康度

正式設定為 Android `compileSdkVersion`／`targetSdkVersion` 36、`minSdkVersion` 24、版本碼 10087，並使用專案 icon 與 adaptive icon。Production EAS 設定已驗證 R8 最小化與資源縮減開啟。依賴稽核沒有發現未經驗證的自訂原生橋接、NitroModules、C++ 模組或為無用功能保留的系統級懸浮窗權限。[2] [8]

本機 Android Hermes export 已成功，表示正式 JavaScript bundle、資產與 Expo 設定可完成打包前輸出。簽署且可安裝的 APK／AAB 仍須在管理介面按 **Publish** 由正式 Android 建置流程產生；本輪沒有在沙盒手動建立 APK，以避免影響開發資源與簽署流程。

## 六、實機發布前驗收

程式層、設定層與 Hermes bundle 已完成，但 Android 系統權限與長時間背景執行仍必須由實機驗收。建議在正式發布前以一台 Android 裝置驗證下列流程。

| 實機情境 | 驗收標準 |
|---|---|
| 開始騎乘與權限拒絕 | 拒絕精確定位、背景定位或通知後，顯示中文引導且不開始不完整騎乘。 |
| 螢幕關閉／背景短程騎乘 | 螢幕關閉後再回到 App，確認軌跡、距離與活動／移動時間連續。 |
| 飛航模式 | 確認既有活動、補給、統計與 GPS 記錄可用；釘選路線失敗只顯示卡片內說明。 |
| 語音 | 在補給到期時只聽到「請補給能量」或「請補給水分」；導航、暫停與到達不播額外語音。 |
| 發布包 | 於管理介面 Publish 後安裝產物，完成至少一次開始、暫停、恢復、停止與儲存活動的流程。 |
