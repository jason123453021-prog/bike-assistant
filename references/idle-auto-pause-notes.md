# 騎乘靜止自動暫停省電設計

現有邏輯以四個低速 GPS 更新自動切換騎乘狀態為 `paused`，但未停止前景 GPS、背景定位任務或前台服務，因此暫停後仍消耗定位電力。背景定位模組已提供可重複呼叫的 `stopBackgroundLocationTracking` 與 `startBackgroundLocationTracking`。

本次功能採預設啟用的兩分鐘靜止逾時門檻：第一次低速自動暫停保留短暫 GPS 觀察；超過門檻才釋放前景、背景定位資源。停止硬體定位後 App 無法自行偵測重新移動，因此恢復必須由使用者按下「繼續騎乘」；這比背景輪詢更省電且避免錯過騎乘紀錄時產生不透明行為。

使用者要求完全自動恢復後，改採低功耗監測而非完全停止：前景定位切換為 Balanced、60 秒／18 公尺，背景任務也切換為同一低頻設定。低功耗監測不寫入軌跡或統計；只要速度達 3 km/h 或位移達 18 公尺，便自動恢復原本高精度模式與騎乘紀錄。

若 App 位於背景，背景任務完成自動恢復後，前景 UI 必須在 AppState 回到 active 時讀取 `trackingMode`；從 `idle_monitor` 變回 `full` 時同步派送 RESUME 並重建完整前景定位訂閱。
